=== C_calibration: motion sampling call sites ===
Round-1 motion sampling override:
  File: isaac_baseline_collect.py (round-1 version)
  Line ~651: env.command_manager._motion_lib.sample_motions = lambda ...
    (overrides MotionLibrary.sample_motions to return forced clip indices)

  BUT: commands.py line ~2825 _resample_command has is_evaluating branch:
    motion_ids = torch.arange(num_envs) % _num_motions
  This bypasses the sample_motions override entirely.

Round-2 fix (B1):
  File: isaac_baseline_collect_r2.py
  Technique: inspect.getsource(_cls._resample_command) → str.replace
    "torch.arange(self.num_envs).to(self.device)"
    → "self._collect_forced_ids.long().to(self.device)"
  Then exec + method.__get__ to rebind the method.
  Result: both eval/paired branches use forced clip indices.

P1 data:
  No re-collection needed per round-2 request (D1 conclusion does not depend on P1).
  P1 was single-joint drive response: 3 joints × step/sine × 27 tests, dt=0.02s.
  The "自洽性问题" was a timestamp labeling bug (dt=0.005 labeled, actual dt=0.02).
  Fixed in v2/v3 delivery; data is valid.
