## 一、前因：我们怎么走到这里

### 1.1 物理层修复（08-14）

渲染验证发现足部穿透 → 诊断发现 **PhysX 训练环境的脚碰撞 box 从未接触地面**（createLink 帧重复应用导致腿链错位 2-3m，脚 box 悬空）。五项修复后（帧修正、自碰撞过滤、contactOffset、踝胶囊移除、root_z_offset=0.04），物理变成真实脚接触行走：PD 基线 9.2→80.7 步，机器人能站、能走、脚底真实着地。

### 1.2 修复物理上的重新标定（08-14 → 08-17）

在修复物理上从零建立训练线：

| 阶段 | 结果 |
|------|------|
| BC warmup（300 iter）| 训练内 59.5 |
| BC trust 阶梯（t05）| 42.2 |
| PPO（300 iter）| 评测 38.5/36.2/27.6 |
| 死亡诊断 | 高度死因归零，踝位置边际超限 70% |
| 踝位置 hinge（1300 iter）| **62.3/58.2/32.9** |
| 渲染反馈 | 抖动严重（踝泵动）→ 速度惩罚 |
| 速度惩罚（1600 iter）| **209.4/165.0/42.1**（宽松阈值 3×，0.20 仅 +28%）|

这一路解决了物理、管线、奖励塑形三类问题，但**每一步都是"权重适应环境"的路线**——并且我们当时不知道自己走的是这条路。

### 1.3 两个意外发现（08-17）

**发现一：我们一直是从随机权重起步的。**
查证：BC-300 的 encoder/quantizer 权重与全新随机初始化逐张量相同（30/30，BC warmup 阶段 encoder 冻结，冻结权重=初始化值，故该比对可判定初始化来源）。SONIC release 权重从未进入过训练。**精确表述**：代码里存在 release 加载路径（`train_agent_trl.py:673-686` 的 `pretrained_model` config——上游原生机制），但**所有 PhysX 运行从未配置它**——修复方式是配置改动（设置路径），不是写新代码。所有成果（最终 209.4/165.0/42.1）都是一个随机初始化的 37M 模型从零学出来的。这很了不起，但也意味着 release 权重的全部先验从未被利用。

**发现二：力矩限幅"机制已对齐，但 4 个关节数值错"。**
XML 实测（29 关节全部带 `actuatorfrcrange`，loader 逐关节读取 ✓）：

| 限幅 | XML 实测 | Isaac CFG | 状态 |
|------|---------|-----------|------|
| ±139 | **2（仅膝盖）** | 6（hip_pitch×2 + hip_roll×2 + knee×2）| **4 个关节未对齐** |
| ±88 | **7（含 hip_pitch/roll×4）** | 3 | 4 个关节差了 37% 饱和上限 |
| ±50 | 6 | 6 | ✅ |
| ±25 | 10 | 10 | ✅ |
| ±5 | 4 | 4 | ✅ |

**修正**：实验三不取消，降级为"修 XML 4 个值"（hip_pitch/hip_roll 的 ±88→±139，一行改动）。**连带警告**：`act_scale = 0.25·effort/stiffness` 的 effort 必须硬编码 Isaac CFG 表（139），不能从 XML 推导（否则 hip_pitch 的 scale 会算成 0.222 而非 0.3507）。

### 1.4 同事实验的旁证

同事（Maxwell-AI-lab）在同一权重、同一引擎上只做了一件事——把动作空间对齐回 Isaac——结果从 4-7 步摔变为零摔倒。这是"环境向权重看齐"路线的单变量实锤。

## 二、核心判断：环境向权重看齐，而不是权重向环境看齐

**release 权重是校准标准，不是交付物。** 两阶段逻辑：

```
阶段一（环境校准）: release 权重 = 校准仪
  已知好的控制器 → 零样本放进环境 → 能走 = 环境正确，摔 = 环境有缺陷
  → 逐层对齐接口（动作空间、驱动增益）直到它走起来
  → 环境与 Isaac 语义对齐完成

阶段二（自主训练）: 随机权重 = 交付物
  在已验证正确的环境里从零训练 → 端到端属于我们的策略
```

为什么这样分：

| 要点 | 说明 |
|------|------|
| release 权重是最干净的验证工具 | 随机训练反推环境质量又慢又混杂；release 零样本一测就定位环境缺陷 |
| 随机训练在正确环境里更快更好 | 已在**扭曲环境**里用随机权重训出 209.4；正确语义下无需浪费容量学"扭曲翻译表"，且验证项目原始目标：NPU 自主训练能力（VLA 计划需要此能力）|
| 环境正确后 release 权重长期驻扎 | ① 回归基准：任何环境改动必须保持 release 权重仍能走 ② 需要时随时可作为微调起点 |
| 两阶段互相成就 | 阶段一产出"release 能走的正确环境"；阶段二的随机训练成果与现有 209.4（扭曲环境随机训练）直接对比 = 环境对齐价值的度量 |

（此前版本的"release 起步微调交付"方案降级为可选路径；交付策略按随机训练。）

### 三层接口模型

网络（权重）与物理环境之间隔着三层接口，每层都可能错位：

```
网络输出 [-1,1] → ①动作空间翻译 → 目标关节位置 → ②驱动器动力学 → 力矩 → ③限幅 → 物理
```

| 层 | 含义 | Isaac 语义 | 我们现状 |
|----|------|-----------|---------|
| ⓪观测空间 | 环境 → 网络的感知接口 | proprio 顺序/单位/归一化、接触标志、相位特征 | **未核对**（历史 g1_recon 需 adaptation 暗示 obs 分布曾与 release 不匹配——实验一失败的候选混淆变量）|
| ①动作空间 | 输出数字 → 关节位移的翻译表 | `default + 0.25·e/k·a`（hip_pitch 输出 1.0 = 0.35 rad）| `jm + jh·a`（1.0 = 2.71 rad，逐关节 0.6×~21.7× 失真）|
| ②驱动器 | 目标位置 → 力矩的机电特性 | armature 反射惯量、10Hz 固有频率、ζ=2、逐关节刚度 14-99 | Isaac 基数已在代码（`_ISAAC_PD`）但被 ×15000/×100000 驱动域缩放（坏物理时代扫描）|
| ③限幅 | 力矩饱和边界 | 139/88/50/25/5（真机规格）| **机制已对齐；4 个关节数值错**（hip_pitch/roll XML ±88 vs CFG ±139）→ 修 XML |

## 四、实验计划

### 原则

- 三个实验**全部零训练**：权重冻结，只改环境侧参数，跑 inference 数存活步数
- 一次只改一层（可归因）
- 每个实验有两个测量：**release 权重零样本** + **ref PD 重测**（PD 基线是动作空间的函数，换空间必须重测）
- 实验顺序：先做最便宜、最可能一击致命的（动作空间），再做需要标定的（驱动增益）

### 实验一：动作空间对齐

**改动**（`physx_env.py`，config 开关 `isaac_action_space`，默认关）：
- `_pd_control`: `target = act_offset + act_scale × action`（逐关节 Isaac 公式）
- `_obs` / `step` 的 ref_action 同步换空间：`(q − act_offset) / act_scale`
- 参数表来自 Isaac 的 `G1_CYLINDER_MODEL_12_DEX_CFG`（同事 E3 已验证的逐关节 effort/armature/default 表）

**判读**：
- release 权重零样本站住/能走 → **动作标度是主因**，主线切换到对齐空间（Phase C）
- 零样本仍秒摔 → 动作空间不是唯一瓶颈，继续实验二
- 无论结果如何，**ref PD 重测是硬性要求**（PD 基线在新空间下重新定义）

### 实验二：驱动增益重标定

**背景**：`_ACCEL_KP_SCALE`（腿 ×15000、腰 ×10000、臂 ×100000）是 eACCELERATION 驱动域的缩放——在**脚接触修复之前**扫描出来的。修复后 PD 9.2→80.7（8.8×）暗示正确增益可能远小于此。正确的换算路径：`kp_drive = k_isaac / I_eff`（逐关节等效惯量），在解析值上下各 2-3 档做小扫描。

**改动**（`physx_loader.py`）：解析计算 + 小扫描（纯环境侧，无训练）。

**判读**：
- 零样本改善 → 增益是元凶，先锁定增益再评估动作空间是否仍要换
- 无差别 → 保留现值（说明 ×15000 在修复物理上仍适用）

### 实验三（降级）：修正 XML 4 个限幅值

hip_pitch/hip_roll 的 `actuatorfrcrange` 从 ±88 改为 ±139（与 Isaac CFG 一致）。一行改动。**注意**：act_scale 表的 effort 值硬编码 CFG 表（139），不得从 XML 推导。

### 决策树

```
实验一成功（动作标度是主因）
  → 切换主线：对齐动作空间 → Phase C（内含新空间增益重扫——×15000 是旧空间
    7.7× 位移下扫的，换空间后必须重扫，不能沿用）
实验一失败 + 实验二成功（增益是主因）
  → 先锁定正确增益 → 再评估动作空间
实验一失败 + 实验二失败
  → 检查第 ⓪ 层（obs 对齐）——未被建模的混淆变量
仍无差别
  → 保留旧线（错配不构成瓶颈），继续旧空间优化
```

### Phase C：对齐环境上的随机权重训练（阶段二）

环境校准完成后（release 权重零样本能走），交付策略训练：
1. **随机权重起步**（与之前相同的随机初始化流程），在已对齐的环境中重走训练线：BC warmup → trust 阶梯 → PPO
2. PPO 沿用已验证的方法论：宽松训练（0.35）+ 严格评测（0.20/0.30）、trust 阶梯、IGNORE_TERM=1、死亡诊断→塑形套路
3. 塑形奖励重新验证：踝 hinge/速度惩罚在正确语义下的必要性重测
4. 对照基准：现有 209.4/165.0/42.1（扭曲环境随机训练）——对齐环境的训练速度/上限应显著更好
5. **主判据 = 0.20 评测**（可检验预测）：扭曲空间增幅结构（0.35 +236%、0.30 +184%、0.20 仅 +28%）支持假设"扭曲动作空间限制的是严格阈值下的鲁棒性上限（精细修正 7.7× 失真，0.20 最需要精细控制）"。若对齐空间在 0.20 无显著提升，对齐假设存疑——这是整个实验的 sharp 证伪标准
6. release 权重全程作为回归基准：每次环境改动后必须重测其零样本表现

### Phase D：迁移验证（必修课）

1. **Isaac 回传**：对齐空间训练的策略送回 Isaac 评测（防"过拟合我们 env"——同事的针尖模型策略回 Isaac 8 步摔是反面教材）
2. **跨片段评测**：12 条动捕全量/留出集，不能只看训练分布上的数字
3. 渲染人检

## 五、保留资产与作废风险

**永久保留**：
- 物理层修复（P0 帧/脚接触/自碰撞/offset=0.04）
- 管线修复（checkpoint 键/fail-fast/掩码/配置去泄漏）
- 方法论：宽松训练+严格评测、trust 阶梯、死亡诊断→塑形套路、PD 可行性第一道关、零训练 A/B 实验模式
- SDK 构建配方、评测渲染管线

**可能作废**（若切换动作空间）：
- 旧空间 checkpoint 数值（209.4/165.0/42.1 等）降级为对照基线
- hinge/速度惩罚的具体权重值（方法论保留，数值需重新验证）
