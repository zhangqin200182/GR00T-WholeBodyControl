# Isaac 侧采集请求 Round-3：free-root + 植定脚承重 stance 响应

> 2026-08-20。前两轮采集的推进已把植物分歧收敛到唯一未测区间：**free-root + 承重 + CFG 忠实软增益 + 耦合链**。此前一切实验要么无载（P1 root-fix）、要么硬增益（mult=10）、要么单关节——本区间恰是 release 策略的工作点。

## 背景（一分钟）

我们的植物在 replay 中与你们的分歧链：接触瞬态 ✅ 健康、静立锚定 ✅ 健康（CoP 模式两引擎同款）→ 分歧 = 近端链（髋/膝）承重下的 stance 相位偏差（0.1-0.26 rad）。髋/膝 load-deflection 用现有数据判不动（我们侧 readback 被接触反力主导，隔离不了驱动输出）。**需要你们录制同协议的承重 stance 响应**，拿到你们的 applied_torque（=驱动输出，你们的字段语义）作为驱动-载荷耦合的对照。

## 采集协议（P1 协议改三点）

沿用你们的 P1 驱动响应协议（27 组：3 关节 × 阶跃 ±0.05/0.1/0.2 × 正弦 0.5/2/5Hz，200Hz 记录，dt=0.02 控制步——与 P1 真实行为一致），改动三点：

1. **free-root**：不锁 root、不 fix——机器人站立、双脚植定地面
2. **锁关节 → PD 持姿**：非扰动关节从"锁死"改为 CFG 原始增益 PD 持姿（**踝不扰动但必须 PD 持姿，不锁死**——踝柔度是 release 载荷路径的一部分，锁死会改变膝看到的载荷）
3. **初始姿态显式**：默认站立 ref 姿态、双脚并立、足底 z = 地面下 5mm（预穿透保证接触约束活跃）

其余不变：CFG 原始增益（kp=armature·ω², ω=2π·10Hz, ζ=2.0——你们的默认驱动配置，勿用任何 stiff 变体）、阶跃/正弦幅度、200Hz 记录、applied_torque/qpos/qvel/target 字段。applied_torque 语义注记：与 P1 相同的 act-then-record 一样本滞后。

**通道补全**：
- **full root_pos/root_quat 时间序列**（非仅 root_drift_max）——free-root 下根是动态变量，q 响应差可能被根摆动驱动
- **contact_force 时间序列（可选但高价值）**：耦合问题的载荷输入，两侧载荷对照才能把"响应差"分解为"载荷差 vs 传递差"

**失衡处理规则**：free-root 下 hip_roll 试次最易翻——规定 root roll/pitch 超阈值或双脚离地即截断，数据保留（触地前可用），reset 重试一次并记录重试次数。

## 预期判读（fork）

- 响应一致 → 近端承重无分歧 → E8 放行（config 侧并行启动）
- 响应分歧 + **载荷同** → 驱动/植物耦合在**传递侧** → 修驱动传递
- 响应分歧 + **载荷差** → 上游**接触侧** → 回头修接触层

**边界备案**：R3 只覆盖双足承重域，不完整覆盖步态单支撑相——若判 null 但 E8 训练后跛行仍现，单支撑变体（单脚植定、扰另一侧）为后备探针。
